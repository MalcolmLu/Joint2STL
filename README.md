# 骨模 · Joint2STL 0.4.4

本地 CT / MRI 肌骨结构工作台，支持膝、肩和全腿分段建模，以及独立或组合 STL 导出。源影像、工程副本与导出数据需保存在仓库之外。

**Windows x64 离线安装包（0.4.4）：** [Google Drive 安装包文件夹](https://drive.google.com/drive/folders/1-NGh9rCF-v9dXTe9pZxqQaEZK1QoPwhA?usp=drive_link)。打开 `Joint2STL-0.4.4-Windows-Installer` 子目录。

安装器文件名为 `Joint2STL-0.4.4-Windows-x64-Setup.exe`（约 3.63 GB）。同目录提供安装说明和 `SHA256SUMS.txt`；访问需要 Google Drive 权限。

0.4.4 修复工具按钮与实际切片模式不同步时，画笔拖动仍移动十字线的问题。开始拖动前统一核对工具，顶部及骨列表下方显示当前编辑标签；按住绘画时不切层，松开后可滚轮切层继续补画。新增“删除当前标签”：删除该标签及全部层面的标注、对应种子和提示点，其他标签保留；可一步撤销 / 重做，空标签也可删除。删除后保存工程不保留失效的标签或种子，三维中对应结构立即隐藏。

MRI 支持膝骨结构候选及 ACL / PCL 标注、存在状态记录和模型框选辅助。影像和模型推理均在本机处理。

0.4.3 增加 MRI 原始矢状层的 **保留点 + / 排除点 −** 和 ScribblePrompt 局部纠错，可用于骨和交叉韧带候选。提示按结构及采集层保存；模型应用可撤销，不覆盖其他标签或已确认缺失的结构。批量精修可选择原 LiteMedSAM 或局部纠错模型；变化过大、提示不受支持或可能漏掉已有分离骨块时保留原结果并提示复核。局部模型只在内部缩放裁剪图，原始 MRI、掩膜网格和物理坐标不降采样。

MRI 面板增加逐层轮廓与覆盖检查，提示封闭空白、多个分离区域、面积突变和单层韧带标注。这些是复核线索，不是准确率或诊断。导出清单记录每个结构的原始采集层覆盖，不能用闭合 STL 或覆盖层数判断韧带是否完整。侧别未指定时，不再把绝对侧方的细长组件直接命名为腓骨，以减少肌腱误命名。

0.4.2 修复 macOS 原生样式下骨标签列表中“选”与颜色块重叠的问题。编辑圆钮、多选方框、颜色与名称分别分配空间；韧带存在状态在名称下方显示，行高随内容调整。长名称可在输入框内编辑，也可悬停查看全文。列表拥挤时垂直滚动，不再压缩行内容。

0.4.0 在 0.3.2 Windows 验证版基础上新增 MRI。保留全腿分段、跨标签归属保护、复核关节间隙保护和多检查选择修复。MRI 使用相对信号及专用骨模型；CT HU 阈值、去床板和皮质补全不会作用于 MRI。

0.4.1 将 MRI 建模来源限定为原始（斜）矢状采集。MRI 默认显示“矢状采集切片＋三维结构”，不显示斜轴位、斜冠状位重排；模型框选、画笔、种子及填充均以矢状采集为依据。其他方向的原始 MR 序列仍可导入浏览，但不能启动三维生成或导出。项目与导出清单记录来源策略、采集方向和序列键，旧项目若已有其他平面的模型标注会在导出前提示重新建立复核掩膜。

## 膝 MRI 标注

1. **导入原始 MR 序列**。MRI 三维建模选择原始（斜）矢状采集，优先核对长 TR 序列，也可手动选矢状 T1。按原始位置计算层间距，保留原网格、LPS 坐标与信号；不会把轴位或冠状序列重排为矢状后冒作矢状采集。其他方向只供浏览。卡片显示 TE / TR、层厚、实际间距及方向；定位片、单层、混合方向及不规则序列不可建模，混合模态或多检查需明确选择。
2. **选择结构**。MRI 提供股骨、胫骨、腓骨、髌骨、前交叉韧带 ACL、后交叉韧带 PCL 标签；空标签可供框选和画笔。未提供明确侧别时显示“未指定”，不根据画面位置猜左右。切片标题按真实采集方向显示；MRI 只显示原始矢状采集，内部数组的第 0 轴不一律称为解剖轴位。
3. **MRI 骨模型初分割**。使用官方 SegmentAnyBone MRI 骨 / 背景模型生成候选，以物理内部标记分离实例，再按物理位置提出骨名。相连骨及不明确组件保留待识别。可先在结构预设中选择目标标签，再用“归属 A”接收已分离骨块；需要拆分时使用不同标签的种子。重新生成只替换当前范围的骨标签，保留韧带和范围外分割；候选可撤销，仍需对照源图。
4. **标注 ACL / PCL**。先选标签，点击“框选标注当前结构”或按 M，在矢状原采集层拖出青色框。LiteMedSAM 按框提出候选；青框不会修改黄色 ROI。默认只处理当前层，邻层传播也只沿相邻矢状采集层（0–4 层）。按需在其他矢状采集层重复框选或用画笔修正，再对已有掩膜逐层精修；不使用斜轴位或斜冠状位模型候选。此功能是提示辅助，没有已验证的 ACL / PCL 专用解剖识别器。
   需要局部纠错时，在工具栏选“保留点 +”，于目标内部放点；用“排除点 −”标记误标的软组织，再点击 MRI 面板“局部模型纠错”。灰度不均或轮廓分成数块时，给每个应保留的部分放点。空标签可先用 M 框选，或沿目标放多个保留点。提示不会直接改动掩膜，可用“清除本层提示”移除；原片中看不清的边界继续保留待评估。
5. **存在状态独立记录**。初次导入默认“未评估”。确认 ACL 缺失时勾选对应选项；其他韧带可在当前状态中确认可见 / 缺失。缺失标签会清空掩膜并阻止模型、画笔、归属和种子生成该结构，状态与清空可一起撤销。空掩膜本身不能证明缺失，模型也不会自动作出缺失判断。
6. **保存与导出**。MRI 项目使用 schema 2，保存原信号、几何、结构类型、存在状态及来源和模型记录；0.4.0 仍可读 schema 1 的旧 CT 项目。新格式需使用 0.4.0 或更新版。按非空结构导出独立 / 组合 STL，已缺失 ACL 不生成虚构 STL；导出清单保留其缺失状态。骨与韧带保持共同 LPS 毫米空间。

STL 表面来自采集数据和掩膜的插值，不能补回采集不到的细节。

MRI 骨模型代码和权重按作者 **CC BY-NC 4.0** 条款用于非商业研究；原 SAM Apache-2.0、TinyViT MIT 及修改来源同时保留。见 `joint2stl/vendor/segment_any_bone/PROVENANCE.json` 和 `models/mri_model_manifest.json`。框选模型继续使用已有 LiteMedSAM。安装 AI / NVIDIA 脚本会校验官方权重，图像不会上传。

局部纠错增加官方 ScribblePrompt-UNet v1，网络与权重来源及 Apache-2.0 许可见 `joint2stl/vendor/scribbleprompt/PROVENANCE.json` 和 `models/correction_model_manifest.json`。安装脚本校验三个固定权重；ScribblePrompt 支持提示驱动的生物医学图像分割，没有已验证的 ACL / PCL 命名分类能力。

0.2.0 增加自动骨名候选、床板 / 石膏 / 夹板 / 外部支具清理，以及四档 STL 表面平滑。已有项目也可使用独立处理按钮；手工确认的名称会保留。

0.2.1 修正 DICOM 推荐，优先明确的软组织薄层，Bone / 锐利核不作自动推荐；加入三平面髓腔填充，并收紧模型的骨外扩张，以改善骨内缺口和关节面多标。

0.2.2 增加 CT 骨缘补全：依据相连的 CT 骨性结构恢复模型漏掉的骨缘，保留现有标签并可撤销；初分割和批量模型精修后默认自动运行，也可单独使用。新增薄骨缘保护限制体素滤波，并显示实际 σ；侧栏滚动不会再修改数值参数。

0.3.0 增加 STL 导出范围及组合方式：勾选骨 / 所有非空骨 / 当前骨，可分别导出、组合为单个 STL，或两种都导出。组合保持各骨相对位置和独立骨壳。骨内填充改为多轮三平面与三维填充；CT 骨缘补全的向外距离限制与封闭髓腔深度分开处理，改善右腓骨等内部残留空缺。

0.3.1 在启动时检测总内存和可用内存，按容量计算体素上限，每次处理前重新检查可用内存。增加骨列表“全选 / 全不选”，方框明确标有“选”，精修按钮显示本次处理数量；骨名预设注明仅用于命名当前骨。

0.3.2 增加「全腿（分段）」：不降采样，在全长原网格上分段初分割，按 26 邻域接合跨段骨块，支持保存和 STL 导出。对于一个目录内的多项 DICOM 检查，序列按检查分别推荐，用户必须选中一项才会载入。批量精修不允许邻骨认领其他标签在本次处理中让出的体素；可从已有工程读取人工复核时保存的关节间隙保护区。

## macOS 启动

在访达中双击 `dist/Joint2STL.app`，或双击根目录的 `启动 Joint2STL.command`。

这是依赖本项目文件夹及 `.venv` 的本机启动器。保留整个项目文件夹；移动文件夹后，可运行 `python3 scripts/create_mac_launcher.py` 重新生成启动器。已运行的旧实例需要退出后重新启动，以载入更新。

首次在另一台 Mac 上运行时，启动脚本会创建环境并安装依赖。需要 Python 3.11 或更高版本，建议 Python 3.12。`Install_AI_Mac.command` 可补装 AI / Metal 依赖及校验官方模型。

## Windows x64 从源码启动

1. 将源码包解压到本地文件夹，安装 Python 3.12 64 位。
2. 双击 `Start_Windows.cmd` 安装并启动基础工作台。安装被网络中断时，可再次运行同一脚本。
3. 双击 `Install_NVIDIA_Windows.cmd` 安装 CUDA 版 PyTorch、CuPy 和模型支持，然后重新启动软件。
4. 在“工具 → 硬件与计算后端”查看检测结果。医学模型使用 `CUDA`、表面后端包含 `NVIDIA GPU / CUDA` 时，两个计算路径分别就绪。

NVIDIA 安装脚本使用官方 PyTorch CUDA 12.8 轮子，需兼容的 NVIDIA 显卡驱动。源码仓库保留模型来源和校验值，模型权重由安装脚本获取。

此修订版包含 Windows MRI 侧栏修复，以及打包版本在中文安装、临时目录中的 CUDA 兼容处理。需要重新构建离线安装包时，参见 [Windows 安装包构建说明](packaging/windows/README.md)。
## 一次完整建模

全腿 CT：导入原始轴位序列后，在「建模部位」选择 **全腿（分段）**，保留完整 Z 范围，再按「全腿分段初分割」。每段深度随当前可用内存调整，跨段的同一连通骨块共用标签。生成的是骨块候选，整腿不自动命名或执行 AI；缩小黄色范围后可对选定骨做原有的 CUDA 精修。髋、膝、踝或足部相接的骨按需用种子分离并核对，交界接触不会因分段而自动断开。全腿 `.j2stl` 可在本版继续编辑，旧版的部位列表不认识全腿项目；膝、肩旧项目仍可在新版本打开。

1. **导入 DICOM**：选择包含切片的文件夹，软件按 Study / Series 分组。优先推荐明确的软组织核、层厚和实际层间距均 ≤1.5 mm 的原始轴位序列。卡片显示重建核、推荐依据、像素尺寸、实际层间距和标称层厚；Bone / 锐利核不自动选中。没有明确的软组织薄层时，需核对后手动选择。重叠重建的较小层间距不会把厚层误判为薄层。
2. **选择范围**：选择膝 / 肩和左 / 右 / 双侧。双侧视野按 DICOM LPS 方向识别左右；单侧扫描请明确选择侧别。“侧别建议范围”按 LPS 方向给出半幅视野建议。用切片上的方向标记核对实际侧别和中线；单侧扫描可用完整视野，再拖动黄色框。三个方向及起止层可分别调整。
3. **自动初分割**：默认下限 200 HU、上限 4000 HU，并启用“自动去床板、石膏和支具”及“初分割后自动识别骨名”。膝部识别股骨 / 胫骨 / 腓骨 / 髌骨候选，肩部识别肱骨 / 肩胛骨 / 锁骨候选。已有分割可单独点击“去床板 / 石膏 / 支具”、“自动识别并命名”和“CT 骨缘补全”。无法可靠区分的骨块保留待识别；相连骨会提示待分离。阈值、最小骨块体积和填孔均可调整。
4. **分离相邻骨**：标为“疑似相连”的区域可能包含多块骨。分别选择不同目标标签，在骨内放种子，运行“种子分离”，再重新识别骨名。“归属”可把点击的整个连通块放进当前标签；勾选“归属仅当前切片”可只修改轴、冠状或矢状重排中的当前层。
5. **模型精修**：骨列表中带“选”的方框支持多选，可点击“全选”。开启“批量精修 / 补全所有勾选骨”后，按钮显示本次处理数量；关闭批量时只处理圆钮选中的当前骨。骨名预设菜单仅用于命名，不限制精修的骨种类。算法从现有骨块生成提示框，由 LiteMedSAM 提出轮廓，结合 CT 高密度骨皮质、骨片保留和层间一致性检查。未采用的模型层可从“异常层”列表跳转核对；后续 CT 补全会单独记录补入的骨性结构。只处理当前黄色范围中有体素的目标标签，批量处理在工作副本中进行，取消时原分割保持完整；应用后可整批撤销。
6. **人工调整**：圆钮选中编辑目标，再按 B 用左键拖动画笔补标、按 E 擦除多余部分；松开鼠标再滚轮切层，所选骨会保持不变。上方“笔刷”单位为毫米半径。画笔把涂到的区域归为当前标签，橡皮仅擦除当前标签。MRI 只改原始矢状采集层；所有画笔操作只改黄色范围内的当前层。“删除当前标签”会删除该标签及所有层面的标注，可一步撤销恢复；只想擦掉局部时使用橡皮。“当前骨髓腔填充”在 CT 结合三平面封闭空隙和三维封闭腔，MRI 仅处理原始矢状轮廓内部。填充和模型精修结束后自动更新三维；画笔等交互修改后可点“更新 3D”。保留最大块、清空当前骨和撤销 / 重做仍可使用。
7. **平滑、保存与导出**：在“STL 表面平滑”选择关闭 / 轻度 / 标准 / 加强，默认标准。预览和 STL 使用相同平滑结果。`.j2stl` 保存 CT、物理坐标、分割、名称及其识别依据、种子、清理及模型检查记录，可在另一台电脑继续编辑。点击“导出 STL”，先选择骨骼范围及文件组合方式，再选择输出位置；每次建立新批次文件夹，清单记录标签、文件、命名来源和平滑变化。

STL 数值单位为 **毫米**，坐标使用 **DICOM 患者 LPS**；各骨保持相对位置。STL 本身不编码单位，导入其他软件时选择 mm。扫描或选区截断的骨端会被封口，代表截断位置。

| 导出范围 | 包含的骨 |
|---|---|
| 列表中勾选的骨 | 左侧列表方框勾选的非空标签，支持多选 |
| 所有非空骨 | 包含未勾选、暂时隐藏的骨；不改变列表勾选状态 |
| 当前骨 | 圆钮选中的编辑目标，即使暂时隐藏也可导出 |

导出方式可选“每块骨独立一个 STL”“所选骨合并为一个 STL”或“同时导出独立文件和组合文件”。例如选两块骨，同时导出会得到 3 个 STL。组合文件保留原始 LPS 坐标，不做布尔融合；STL 不保存骨名和颜色，标签对应及组合中的三角面范围见 `export_manifest.json`。相接骨壳在其他软件合并顶点后可能形成非流形边，导出检查会如实报告，需结合独立文件复核。

## 自动命名与外部结构清理

骨名候选依据已有骨块的 LPS 位置、左右关系、体积及形态规则生成。自动名称保留“待核对”状态，人工改名会标为手工确认并受到后续自动命名保护。命名与掩膜编辑共用撤销 / 重做顺序。复杂相连骨、较小骨片、扫描截断及侧别不明时可能无法命名。

床板和外部固定物清理从完整采集切片识别软组织轮廓，再结合结构与人体的连接关系排除外部高密度结构。石膏壳、夹板、支具也参与检查。与骨连接、重叠或轮廓不明确的部分会保留并提示复核；部分结构仍可能残留。清理只修改分割，保留原始 DICOM 和 HU，可撤销。

骨内填孔保留过大的封闭空隙，避免石膏或皮肤高密度边缘将整片软组织围成“实心骨”。建议先完成外部结构清理、核对骨标签，再使用本地模型精修。

## 模型边界与骨内填充

0.2.1 模型提案相对提示轮廓的向外增长上限为 1 mm，并以较强骨密度作种子、连接较弱皮质形成多平面包络约束边缘，允许 0.8 mm 的边缘余量；保留已有 ≥450 HU 的皮质及实体内部。CT 皮质依据不足或模型变化异常的层保留原分割。参数是工程约束，不代表已知的解剖误差上限；仍需检查关节面、真实骨孔和小骨片。

## CT 骨缘补全与薄骨缘保护

“CT 骨缘补全”按“批量精修 / 补全所有勾选骨”设置作用于当前骨或勾选骨。程序用 CT 皮质和现有标签共同确定归属，邻骨标记参与竞争分界；在有限范围内补回相连骨缘及包络内部，现有非零标签保持不变。补全在工作副本中完成，可撤销，记录随项目保存。原始 CT 保留；补全依据和大范围变动仍需核对。

0.3.0 将向外补回骨缘的距离限制与骨内填充分开：恢复皮质后，封闭的骨内部可填到髓腔深处。三平面和三维填充最多循环 6 轮，提前达到稳定时停止。仅填充现有轮廓包围的空间，不对外轮廓作膨胀，也不覆盖其他标签；真实骨孔仍需核对。

“保护薄骨缘”默认开启，将实际体素滤波 σ 限制在最小采集体素间距的一半；界面和导出清单显示实际应用值。这样可保留薄骨缘，并通过独立的保形表面平滑减少阶梯纹。数值输入使用键盘或箭头，滚轮用于侧栏和切片浏览。

## STL 表面平滑

“体素滤波 σ”处理二值体积；“STL 表面平滑”进一步处理原始分辨率三角表面。四档表面设置分别为关闭、位移上限 0.15 mm、0.30 mm、0.50 mm。平滑限制每个顶点的位移、原表面有向体积变化（最多 1%）及相对面片翻转，不减少三角面数。它会改变表面几何，不能据此证明解剖精度提高。清单报告实际变化，便于检查骨缘和关节面。

## 动态内存上限与 GPU

启动时通过系统接口读取总内存及可用内存，侧栏显示当前初分割和精修上限。“工具 → 硬件与计算后端”提供各阶段的完整预算。运行初分割、外部结构清理、种子分离、模型精修或 CT 补全前，会重新读取可用内存；释放其他程序的内存后可直接重试。

| 总内存 | 初分割 / 外部结构清理 | 模型精修 / CT 补全 / 种子分离 |
|---|---:|---:|
| 16 GB | 1.6 亿体素 | 1 亿体素 |
| 32 GB | 3.2 亿体素 | 2 亿体素 |
| 64 GB | 6.4 亿体素 | 4 亿体素 |

表中是可用内存充足时按容量计算的上限，使用 GiB 容量计数。当前可用内存不足时会进一步降低；各阶段预留系统空间和固定开销，并采用不同的每体素额外内存估算。单阶段还有 8 亿体素的实现上限。检测失败时使用保守的 8 GB 配置。这些预算是工程估算，不能保证实际峰值或处理速度；较大数据仍适合先框选关节。系统 RAM 的增加不会相应增加显卡显存预算。

- 三维显示由 VTK 的 OpenGL 后端使用系统 GPU。预览和导出共享原始分辨率表面，未改动的网格会复用；修改掩膜后重新生成。几何缓存上限为 96 MiB，另有网格处理及渲染开销。
- 表面滤波支持 CPU、Apple Metal（MLX 自定义核）及 NVIDIA CUDA（CuPy）。自动模式对小体数据使用 CPU，对合适规模使用可用 GPU；自动模式遇到 GPU 运行时或内存错误会回到 CPU。
- 医学模型自动选择 CUDA、Apple MPS 或 CPU。推理使用 FP32；CUDA TF32 被关闭，以保持数值精度。
- 连通域、种子分水岭、网格拓扑检查和格式写入使用 CPU。GPU 加速某个阶段的倍数不等于完整建模的提速倍数。
- 笔刷统计采用增量更新，计数采用分块处理，减少大卷数据上的内存峰值。批量目标数量按当前范围统计并缓存，勾选或切换编辑目标不复制 CT / 分割数据。

可在自己的数据上运行性能工具：

```sh
python -m scripts.benchmark --project /path/to/项目.j2stl --output gpu-benchmark.json
python -m scripts.benchmark_render --stl-dir /path/to/STL输出 --output render-benchmark.json
```

滤波测试包含 CPU / GPU 数据转换，分别报告首次与预热后的耗时。渲染测试为离屏绘制，支持时会等待 GPU 完成；实际窗口交互仍需实测。

## 精度与支持范围

当前是可编辑原型。真实膝 CT 已完成读取、分割、自动命名候选、去床板、项目恢复、模型精修、表面平滑和 STL 回读检查。肩部具备相同处理工具及骨名规则，尚缺真实肩关节 CT 的验证。石膏、夹板和支具功能已做受控几何回归，尚缺确认带有这些固定物的真实病例验证。

模型提供轮廓建议。现有测试没有人工参考分割，不能据此报告建模误差、Dice 精度或“已替代专家标注”。异常检查和模型自身评分也不是经校准的解剖准确率。薄骨皮质、相接关节面、分离骨片、金属与扫描边缘需结合源图检查。像素大小和层间距不能直接当成建模误差；插值和平滑会改变表面。

初版支持规则、普通单帧、线性 HU 的原始轴位 CT。会排除定位片、报告、渲染截图、增强多帧、非 HU 数据、非线性模态 LUT、缺层或不规则间距。保持采集网格及其物理方向；倾斜序列的重排沿采集网格，存在平面内漂移的序列会拒绝导入。

## 开发、测试与项目来源

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[ai,metal,test]'
.venv/bin/python scripts/setup_models.py
.venv/bin/python -m pytest -q
.venv/bin/python -m joint2stl
```

Windows 对应解释器为 `.venv\Scripts\python.exe`。Qt 固定为当前验证组合 6.8.3；本机曾发现新版 Qt 与原生 VTK 的重复绘制问题。

工作流参考 [3D Slicer Segment Editor](https://slicer.readthedocs.io/en/latest/user_guide/modules/segmenteditor.html) 与 [Segmentations](https://slicer.readthedocs.io/en/latest/user_guide/modules/segmentations.html) 的切片编辑、多标签及 STL 导出设计。

SlicerSegmentHumanBody、NIAID dicom2stl 与 DicomToMesh 的适用部分及采用记录见 [项目参考与许可来源](docs/PROJECT_REFERENCES.md)。

本地医学模型采用官方 [LiteMedSAM](https://github.com/bowang-lab/MedSAM/blob/LiteMedSAM/README.md)。仅纳入必要推理层，来源提交及修改说明见 `joint2stl/vendor/medsam_lite/PROVENANCE.txt`；保留 Apache-2.0、原始版权头与 TinyViT 的 MIT 许可。权重来自官方 README 链接，文件信息及 SHA256 在 `models/model_manifest.json`；加载采用固定校验和及 `weights_only=True`。

GPU 路径使用 [MLX Metal](https://ml-explore.github.io/mlx/build/html/python/metal.html)、[CuPy Gaussian filter](https://docs.cupy.dev/en/stable/reference/generated/cupyx.scipy.ndimage.gaussian_filter.html) 和 [PyTorch MPS / CUDA](https://pytorch.org/get-started/locally/)。
